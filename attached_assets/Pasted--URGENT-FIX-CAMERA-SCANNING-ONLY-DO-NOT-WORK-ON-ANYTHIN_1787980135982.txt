# STEP 3 — OCR MUST PRESERVE INFORMATION ACCURATELY

This is extremely important.

The camera feature is intended to scan real-world documents/images such as:

* Books
* Notes
* Printed pages
* Worksheets
* Documents
* Menus
* Posters
* Tables
* Forms
* Lists
* Multi-column content
* Images containing mixed text and numbers

The OCR result must preserve the **actual information** in the image.

Do NOT aggressively simplify or rewrite the information during OCR.

For example, if the image says:

| Item  | Quantity | Price |
| ----- | -------- | ----- |
| Apple | 2        | ₹100  |
| Mango | 3        | ₹150  |

The system must NOT turn this into something vague such as:

"Apples and mangoes are available at different prices."

The actual information must be retained.

# STEP 4 — TABLE DETECTION AND PRESERVATION

If the scanned image contains a table, the system must recognize that it is a table and preserve its structure.

Do NOT extract table contents as a random sequence of words.

Bad output:

Apple 2 ₹100 Mango 3 ₹150

Good output:

| Item  | Quantity | Price |
| ----- | -------- | ----- |
| Apple | 2        | ₹100  |
| Mango | 3        | ₹150  |

If Markdown tables are the most reliable way to represent the table in the existing UI, use Markdown tables.

If the application's UI has another suitable table representation, use that instead.

The important requirement is:

**Rows, columns, headings, values, and their relationships must remain understandable.**

The table should remain readable even after formatting/simplification.

# STEP 5 — CLUTTERED RESTAURANT MENUS

A particularly important use case is a **cluttered restaurant/menu image**.

Menus may contain:

* Multiple columns
* Food categories
* Item names
* Prices
* Descriptions
* Vegetarian/non-vegetarian indicators
* Multiple prices
* Items aligned visually rather than sequentially
* Different font sizes
* Sections
* Decorative elements
* Images
* Several unrelated blocks of text

Do NOT simply read the image from top-left to bottom-right and dump the OCR text.

That can produce completely jumbled output.

Instead, preserve the logical structure.

For example, if the image contains:

STARTERS

Paneer Tikka ........ ₹220
Veg Manchurian ...... ₹180

MAIN COURSE

Paneer Butter Masala  ₹250
Dal Tadka ............ ₹180

The output should retain the categories and relationships:

## Starters

| Item           | Price |
| -------------- | ----: |
| Paneer Tikka   |  ₹220 |
| Veg Manchurian |  ₹180 |

## Main Course

| Item                 | Price |
| -------------------- | ----: |
| Paneer Butter Masala |  ₹250 |
| Dal Tadka            |  ₹180 |

Do NOT randomly mix prices with unrelated food items.

# STEP 6 — PRESERVE READING ORDER AND LAYOUT

For complex images, OCR should consider **document layout**, not just individual words.

The system should attempt to determine:

* Reading order
* Paragraph boundaries
* Headings
* Subheadings
* Columns
* Tables
* Lists
* Key-value relationships
* Menu categories
* Item/price relationships
* Separate blocks of information

The final output should represent the logical structure of the original image.

If the source has two columns, do not arbitrarily merge lines from both columns.

If the source has separate sections, preserve those sections.

If there is a heading, keep it as a heading.

If there is a list, keep it as a list.

If there is a table, keep it as a table.

# STEP 7 — FORMATTING/SIMPLIFICATION MUST NOT DESTROY STRUCTURE

This is another major requirement.

AksharAlly is supposed to make content easier to read.

However:

**Simplifying text does NOT mean destroying its original information structure.**

The formatting/simplification stage must NOT:

* Shuffle information
* Merge unrelated lines
* Separate values from their labels
* Mix table rows
* Mix table columns
* Move prices to different items
* Remove important numbers
* Remove important headings
* Randomly reorder content
* Turn structured information into a paragraph
* Produce visually jumbled output

For example, if OCR produces:

| Item           | Price |
| -------------- | ----: |
| Paneer Tikka   |  ₹220 |
| Veg Manchurian |  ₹180 |

The formatted/simplified output must retain this structure.

It can make the text more readable, but it must not destroy the relationship between:

**Item → Description → Price**

or:

**Column heading → Cell value**
