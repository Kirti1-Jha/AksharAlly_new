Redesign the Settings screen completely and transform it into an **Accessibility Center** for AksharAlly.

IMPORTANT REQUIREMENT:

The accessibility settings should affect ONLY the application's UI text and interface elements. They must NOT affect OCR output, uploaded text, PDF content, simplified text, or reader content because content formatting is already handled separately in the Reader screen.

### Scope of Global Accessibility Settings

The following UI elements should automatically inherit accessibility preferences:

* App title (AksharAlly)
* Screen titles and headings
* Buttons
* Navigation bar labels
* Cards
* Dialogs and popups
* Settings page text
* Library page text
* Home page text
* Empty states
* Error messages
* Future screens and components

The following should NOT be affected:

* OCR extracted text
* Uploaded PDF content
* Uploaded image text
* Simplified text output
* Reader content
* Any user-provided reading material

These remain controlled by the existing Reader customization features.

1. Dyslexia Recommended

   * Lexend font

2. Low Eye Strain

## Technical Requirements

Create a centralized AccessibilitySettings model that stores:

* fontFamily
* fontSize
* letterSpacing
* wordSpacing
* lineHeight
* textColor
* backgroundColor
* boldTextEnabled
* highContrastEnabled
* reducedAnimationsEnabled
* largeTouchTargetsEnabled

Persist settings using SharedPreferences.

Load settings when the app starts.

Apply settings globally through a centralized theme provider/state management solution so that all UI text across the application updates automatically.

Do NOT hardcode styling inside individual screens.

Use the accessibility settings as the primary source of truth for UI typography and colors.

Changes should take effect immediately without requiring an app restart.

The goal is to make the entire AksharAlly interface dyslexia-friendly while keeping reading-content customization completely separate.
