AksharAlly Redesign & Workflow Refactor Specification
Core Product Principle

AksharAlly supports TWO separate workflows.

1. Format Only
Purpose

Improve readability without changing meaning.

Actions include:

Better line breaks
Better spacing
Chunking long paragraphs
Dyslexia-friendly presentation
Reader-friendly layout
Must NOT
Rewrite sentences
Change vocabulary
Translate text
Simplify meaning
Format Only Implementation

Format Only must NOT call Gemini.

For Format Only mode:

OCR/Image Upload

Image → OCR → Reader

File Upload

Document → Text Extraction → Reader

Typed Text

Text → Reader

Apply only presentation formatting:

Paragraph chunking
Line breaks
Dyslexia-friendly spacing
Reader layout improvements

Do NOT:

Rewrite sentences
Change vocabulary
Translate content
Simplify meaning

This mode should be implemented entirely in Flutter and should not invoke AI processing.

2. Simplify + Format
Purpose

Make complex content easier to understand.

Actions include:

Sentence simplification
Easier vocabulary
Shorter sentence structures

After simplification, apply the same dyslexia-friendly formatting used in Format Only mode.

This mode may use the existing Gemini-based backend pipeline.

Language Preservation Rule

Formatting must preserve the original language.

English input must remain English.

Hindi input must remain Hindi.

Format Only must never translate content.

Simplify + Format may simplify language but must never change the selected language.

No automatic translation should occur anywhere in the workflow.

API Contract Protection

Do not rename:

Existing endpoints
Existing request fields
Existing response fields

Do not modify backend routes unless explicitly required.

The redesign should primarily affect the Flutter UI layer.

Any backend change must be justified and reported before implementation.

Architecture Protection Rules

Do NOT:

Delete files
Remove routes
Remove widgets
Remove services
Remove backend modules
Refactor project architecture
Change folder structure
Rename files
Rename classes
Rename APIs

unless explicitly instructed.

Focus on implementing the redesign requirements while preserving the current architecture.

Critical Requirement

Do not remove or break any currently working functionality.

The following features must continue working exactly as they do today:

Firebase Authentication
OCR extraction
PDF upload processing
DOCX upload processing
Gemini integration
Library save/load
Reader screen
Word highlighting
TTS controls
Existing API integration
Language selection
Existing navigation flows

If a redesign risks breaking an existing feature, preserve the current implementation and only refactor the UI layer.
